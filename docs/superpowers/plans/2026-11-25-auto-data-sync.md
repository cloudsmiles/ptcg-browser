# 自动同步与服务器部署实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 按任务顺序实施。

**Goal:** 将项目提交到 cloudsmiles/ptcg-browser，并在指定服务器提供可自动同步中文卡牌的网站。

**Architecture:** 独立同步入口固定上游提交后下载、隔离构建、校验并切换数据入口。网页使用带版本的索引和详情，服务器每天运行同步任务；GitHub Actions 运行回归检查。

**Tech Stack:** Python 3、Node.js 22、systemd、Nginx、GitHub Actions。

**Spec:** docs/tech-design/20261125-AutoDataSync.md

## 全局约束

- 服务器已有网站，新增 `/ptcg/` 反向代理与独立服务；不得覆盖现有站点。
- 不将 SSH 密码或登录凭据写入仓库。
- 下载和校验失败保留当前数据；不清理旧索引和详情。
- 首期仅同步中文；默认每天北京时间 04:15 检查。

## 审查重点

- 下载失败、源数据结构变化和数量骤减不能破坏已发布版本。
- 已打开页面后续加载索引和详情仍访问原版本。
- `/ptcg/` 子路径中的缩略图请求必须正确路由。
- 无变化时不重建，转换脚本改变时应重建。
- 服务以独立低权限用户运行，构建目录和缓存可写，代码与凭据不可经 HTTP 读取。
