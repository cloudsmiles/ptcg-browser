# 首屏先展示，完整索引延迟加载

## 加载顺序

1. 加载页面样式、首屏数据 `data/zh-bootstrap.js`、加载器和交互脚本。
2. 用默认排序前 48 张初始化页面并发起缩略图请求；首屏数据约 102 KB，gzip 约 8.7 KB。
3. 两次 requestAnimationFrame 后延迟 500 ms，再通过 requestIdleCallback（最长等待 1.5 秒）启动低优先级完整索引请求。
4. 完整索引就绪后，原位替换数据引用并开放全量搜索、筛选和加载更多。首屏节点不重新插入，滚动及已打开详情不重置。

完整数据未就绪前显示状态说明并禁用全量查询，避免把 48 张的子集当作全量搜索结果。卡片详情仍可打开，完整索引失败后首批卡片继续可用，并提供重试。

## 验证

Chrome 150，1440×900，固定第三方图片响应，3 次运行取中位数：

| 指标 | 上轮 | 当前 |
|---|---:|---:|
| 首卡片就绪 | 541.6 ms | 257.7 ms |
| 首卡片就绪时本地资源传输（不含卡图及 HTML） | 1,308,206 bytes | 31,582 bytes |
| 加载更多中位耗时 | 14.7 ms | 14.7 ms |

两组顺序执行，系统负载未严格控制。首卡片就绪是首次节点插入后的动画帧时间，不等同于真实卡图下载完成或 LCP。完整索引随后仍要下载和在主线程解析，不计入上述首屏资源采样。

- 浏览器阻塞完整索引时，首屏卡片仍能显示；失败后重试可恢复全量 24,544 张数据，皮卡丘搜索结果为 429 条。
- 首批 48 张记录及详情定位与完整索引默认前 48 张逐项一致。
- 桌面/手机搜索、详情、空结果、长列表尾部、尺寸变化和滚动稳定性继续回归。
- 复现：按 README 配置 PLAYWRIGHT_CORE 后运行 `node scripts/browser-deferred-index.cjs`。

原始记录：[延迟索引性能数据](performance-deferred-index.json)。

## 边界

本次将完整索引移出首屏关键路径，并未把索引解析迁入 Worker；后台解析期间仍可能出现短暂主线程长任务。仅加载用户浏览到的卡图，不执行缩略图预热。
